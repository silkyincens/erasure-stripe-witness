# ErasureStripeWitness design / API / test plan

AI-assisted independent prototype for a public polynomial-coded stripe, not secret sharing, error correction, publisher identity or guaranteed data availability. All examples are synthetic local HTTP mocks with real public URL null. No deployment/publication/live claims.

Owner registers an immutable commit-pinned raw GitHub strictJSON URL and exact bytes SHA. One document contains the actual complete shard symbol vectors, not metadata about un-fetched payloads. Shape exactly `{"version":1,"k":2,"shards":[{"x":1,"values":[8,9]},...]}`. Field is fixed prime257. Exact integer k2..8; n=k+1..12; x unique integer1..256; equal vector widths1..16; every symbol exact integer0..256. Bool/NaN/duplicatekeys/extra fields and invalidUTF8 fail. Source1..16384 bytes. Namespace owner/repo/40hex/path are explicitly separated and dot repository/path segments rejected.

Sort shards by x, interpolate each column using the first k points with finite-field Lagrange arithmetic (ascending-degree coefficients, every operation modulo257). Verify every actual shard, including every redundant point, against recovered coefficients. Return field/k/columns/basis_x/candidate_coefficients, CONSISTENT or INCONSISTENT, and the first mismatch ordered by (x,column). On consistency only, data_sha256 hashes canonical coefficient matrix; this identifies declared polynomial data, not a decoded real file. Inconsistent basis interpolation is only a candidate, not identified correct data. No detection/localization guarantee for corrupt basis points or malicious but consistent codewords. Complexity bounded by n<=12, k<=8, width<=16.

Leader and validator each fresh-fetch/hash/strictparse/reinterpolate/verify all points and derive the full canonical packet. Full binding protocol/chain/contract/owner/stripeID/URL+SHA/registeredAt/revision/certifier/time; no leader-supplied polynomial/schema-only acceptance. Owner-only register unused ID -> REGISTERED0; anyone certify(id,expectedRevision) once -> CERTIFIED1; owner exactcert+CAS activate only CONSISTENT -> ACTIVE2; owner terminal offline revoke from any nonterminal phase. Max8 lifetime stripes, history<=4, IDs never recycled. Views get_stripe/is_active/configuration and verify_shard(id,expectedRevision,cert,x,values_json) -> bool: only exact current ACTIVE, x0..256 and bounded exact integer vector matching all certified column evaluations. Query does not fetch/prove external availability. Negative/malformed/unavailable source preserves registration or retained negative certificate as appropriate.

Before implementation tests: actual SDK minimal-API red; literal two-column recovery, GF wrap/inverse, shuffled canonical input, all-redundant mismatch with first witness, negative activation, current ACTIVE evaluation and crossrecord replay; validator rejects forged full-shaped coefficients/status/witness/datahash/binding and fresh changed/unavailable bytes; k/n/x/vector/symbol/type/size/strictJSON limits, valid max dimensions, URLdot namespaces; owner/CAS/certificate/terminal/history/capacity. No host interpolation solver: literal expected coefficient matrices and simple evaluation/replay only. Retain actual red->green, full exact GenVM0.2.12 direct suite + complete semantic lint/schema/0ctor, README/threat limits/manifest/safe ZIP, independent frozen-source review.
